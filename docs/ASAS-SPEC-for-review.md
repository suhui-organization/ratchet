# Agent 安全验收标准（评审稿）

> **这份文档是给评审人看的**，不是产品介绍。目标只有一个：
> 判断**一个客户或审计员，能不能拿它当验收条款用**。
> 评审人不需要懂我们的产品，只需要判断这份东西**能不能被检查**。

---

## 1. 一页导读

**要解决的问题**：企业把 agent 接进业务系统后，被客户、审计或监管问到同一个问题——
*"这些 agent 到底被允许碰什么？你凭什么这么说？"* 今天没有可交付的答案。

**这份标准要求什么**：不是要求装什么产品，而是要求**能产出一份可被第三方独立核验的凭据**。

**它最硬的一条**：验证方**不需要联网、不需要装任何东西、不需要信任签发方**。

## 2. 客户要做的三件事（这就是全部动作）

1. **采集**：在范围内列举 agent、它们可达的组件（MCP server / skill / 工具）、以及每条访问判定的依据。
2. **出证**：把这些产出成一份机器可读的凭据（字段格式见 `spec/ASAS-A-v0.1.schema.json`）。
3. **交证**：把凭据连同证据文件交给收货方。

**收货方不做任何准备工作**，用任意实现跑一遍验证程序即可。

## 3. 验收清单（客户/审计员照着打勾）

| # | 检查项 | 怎么验（不需要我们的工具） | 不通过意味着 |
|---|---|---|---|
| 1 | 证据文件哈希一致 | 重算 sha256 与清单比对 | 交付物被动过 |
| 2 | **委派只可收窄** | 子 agent 的作用域 ⊆ 父 agent；父不在凭据里即不合规 | 权限被悄悄放大 |
| 3 | **未知已声明** | 拿不到哈希/版本/定版状态/工具面的项，都出现在 `unknown[]` 且有原因 | 用"看起来干净"掩盖了盲区 |
| 4 | 每条判定都有依据 | 任一 allow/approve/deny 的 `basis` 为空即不合规 | 判定不可复核 |
| 5 | 组件已定版或有未过期豁免 | `pinned=false` 必须有到期日（开放式豁免不合规） | 供应链可被替换 |
| 6 | **沉默可被审计** | 事件序号连续、前序哈希相符 | 监控数据可被删改而不被发现 |

**六条全部通过 = L3（可证明）**；再满足"变更重证 + 遏制演练"即 **L4（持续）**。

## 4. 标准明确**不**覆盖什么

- **不覆盖**模型对齐、提示词护栏、内容安全（那是模型厂商的层，概率性的）；
- **不声称合规**：它只说明"这份证据能支撑哪一条要求"（EU AI Act / ISO 42001 / SOC 2 / NIST AI RMF）；
- **不要求拦截**：只读治理（`mode: readonly`）是合法答案，但**必须显式声明**，不能含糊。

## 5. 请评审人回答的五个问题

> 前四个决定这份标准有没有用，第五个决定它能不能被行业接受。

1. **作为验收条款**：如果你在客户合同或内部审计里看到第 3 节这六条，你能照着判吗？哪一条判不了、为什么？
2. **作为交付条件**：如果供应商交上来这样一份凭据，你会接受吗？**你会额外要求什么？**
3. **缺失项**：你实际工作时会问、但这份清单没覆盖的问题是什么？
4. **成本感受**：让你（或你的客户）产出这份凭据，你觉得合理的工作量是多少？超出多少就不做了？
5. **中立性**：这份标准由一家厂商起草。**什么样的条件能让你相信它是中立的**？（例如：移交 OWASP/CSA、公开评论期、为竞品盖章——我们愿意做，但想知道对你是否够）

## 6. 我方承诺（写在标准之外的商业承诺）

- 规范文本 **CC-BY-4.0**：任何人都可以实现，不需要买我们的东西；
- 出现 **1 个外部实现 + 1 个审计方引用**后，规范**移交中立组织**（OWASP 项目 / CSA 工作组）；
- 我们**愿意为竞争对手的实现出具认证**——否则它就不是标准。

## 7. 一页纸的样例（评审人可照着走一遍）

```jsonc
{
  "asas": "0.1",
  "subject": { "org": "acme", "period": { "from": "...", "to": "..." }, "scope": ["codex agents on macOS"] },
  "agents": [{ "id": "codex", "owner": "alice", "identity": { "type": "service-account", "shared": false } }],
  "assets": [{ "kind": "server", "name": "kubernetes", "pinned": false, "exemptUntil": "2026-10-20T00:00:00Z",
               "contentHash": "sha256:…", "descHash": "sha256:…", "reachableTools": 23 }],
  "verdicts": [{ "agent": "codex", "asset": "kubernetes", "decision": "deny",
                 "basis": "name matches \"delete\"" }],
  "unknown": [{ "what": "filesystem: contentHash", "why": "本机扫描拿不到制品本体", "discoveredAt": "..." }],
  "observations": [{ "tool": "read_file", "count": 12, "argKeys": ["path"] }],   // 注意：没有参数值
  "boundaries": { "mode": "readonly", "revocationMinutes": 0 },
  "manifest": { "evidence": [{ "file": "policy.json", "sha256": "…" }], "generatedAt": "…", "generator": "…" }
}
```

> 两个细节请特别留意，它们是这份标准与其他清单的分水岭：
> **`unknown[]` 里的东西比 `assets[]` 更能说明诚实**；`observations` 里**没有**放参数值的位置。
