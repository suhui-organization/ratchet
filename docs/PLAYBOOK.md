# 交付操作单

> 目标：**两周内做完 3 次真实交付**，用它换取唯一有效的证据——
> 有没有人愿意为这个付钱。
>
> 纪律：这三次的目标不是赚钱，是**证伪**。所以流程里每一次都写清了
> "该看什么信号"，而不是"该怎么说才能成"。

---

## 0. 先接受三件事

1. **大概率没人付钱。** 三次里能有一次真金白银就是好结果。把它当成一次昂贵的调研。
2. **不要卖。** 一卖对方就开始客气，你拿到的全是假信号。你要问的是**过去发生过什么**。
3. **交付本身要真的有用。** 哪怕对方最后不买，他也应该拿到一份能直接用的东西——
   否则你烧掉的是自己的信誉。

---

## 1. 找谁（这是最难的一步，占一半工作量）

**画像**：给企业做 AI 落地的小乙方 / 工作室 / 独立顾问。
特征是他**要替客户回答"这个 agent 能碰什么、做过什么"**。

为什么不是开发者个人：他不为安全感付钱。
为什么不是大企业 CISO：你进不去他的采购流程。

> **先纠正这一节最初的错误**：它原本写的是"从你认识的 10 个做 AI 交付的人开始"。
> 如果你有这个网络，你根本不需要这个工具。**没有网络才是默认情况**，
> 下面的顺序按"一个熟人也没有"来排。

| 渠道 | 具体动作 |
|---|---|
| **① 已经公开说出这个痛处的人** | 唯一不需要关系、也不需要运气的渠道：他们**自己**在公开场合抱怨过。去搜，然后回他一句有用的东西 |
| ② 你自己的机器 | 用你本机的真实环境出一份报告并公开。**不需要任何人同意**，它同时是证据和钓饵 |
| ③ 公开社区 | 即刻 / V2EX / X / r/mcp / HN —— 带**具体数字**发，不带形容词 |
| ④ 冷启动私信 | 效率最低，靠量堆：私信 100 个 ≈ 5–10 回复 ≈ 2–3 次对话 ≈ 1 次交付 |

**渠道 ① 怎么搜**（X / GitHub / Reddit / HN 里搜这些）：

```
MCP security        agent permissions     最小权限 MCP
tool poisoning      未锁版本 mcp server    MCP 网关 策略
"agent 权限"        shadow mcp server
```

谁在抱怨"不知道 agent 能碰什么"、谁被客户问过、谁的 MCP server 挂了一堆——
**这些人是自己举手的人**，你回复他不是打扰。

回复不要提产品，只贴一个事实：

> 我扫了本机 16 个 MCP server，12 个没锁版本。你这边呢？

**目标数量**（没有网络时的现实值）：找 30 个公开抱怨过的人 → 回帖或私信 →
期望 3–5 个回应 → 3 个愿意做。

---

## 2. 开场怎么说（可直接复制）

不要太长，不要提产品名，不要提"安全"。

> 我在做一个工具：把你这台机器上 agent 能干的活扫出来，出一份权限收敛的清单，
> 顺便把"它实际用过什么"记下来。
>
> 我想找 3 个人免费做一次，不要钱，也不推销——**做完你留着那份报告，觉得没用就直说**。
>
> 想先问你一个问题：**你上一次被客户问"这个 agent 到底能碰什么"，是怎么回答的？**

最后那个问题是整个流程的核心。**不要问"你会不会买"，要问"上一次你是怎么熬过去的"。**

- 如果他说"没被问过" → 他不是你的客户，换下一个，别浪费两次沟通。
- 如果他说"就大概讲一下" → 有戏，接第 3 步。
- 如果他说"我写了个文档/截了图给他" → **最好的信号**，说明他在为这件事花时间。

---

## 3. 做交付（30–60 分钟，远程或当面）

**前提**：在**对方机器上**做，或者你在自己机器上演示。前者效果好得多。

```bash
# 0) 构建（你已经有了）
cd /home/walden/Workspaces/ratchet && go build -o bin/ratchet ./cmd/ratchet

# 1) 只读扫描：这一步不执行任何东西，先让对方看到"他知道的东西"
./bin/ratchet scan --home ~ --workdir ~/他的项目目录
```

**该说什么**：把扫出来的数字念给他听，尤其是**未锁版本的依赖数**。
这一步的目的是建立可信度："它没有乱动你的东西，只是读了你本来就有的配置。"

```bash
# 2) 问一句再继续（这一步会执行他的 MCP server）
#    "下一步我要连上这些 server 问它们有哪些工具，会启动它们。可以吗？"
./bin/ratchet scan --home ~ --introspect --allow-exec --out inventory.json

# 3) 如果有历史调用记录就对上；没有就跳过
./bin/ratchet observe --calls ~/.ratchet/calls.jsonl --inventory inventory.json --out used.json

# 4) 编译策略（第一次交付用默认模式，别急着 --only-observed）
./bin/ratchet policy draft --from used.json --out policy.json

# 5) 出交付包
python3 service/src/ratchet_service/cli.py build --dir delivery --policy policy.json --bundle share.json
```

**该看什么**（这比该说什么重要）：

| 观察 | 含义 |
|---|---|
| 他在 `scan` 那一步就凑过来看 | 兴趣真实 |
| 他看到"从未被调用"那批时说了"这个我还真没用过" | **最强信号**：你给了他一个他自己不知道的事实 |
| 他在策略里看到某个工具被收成 approve 时皱眉 | 触到了真实工作流，问他为什么 |
| 他全程礼貌点头，不提问 | 你不该继续投入这个人 |

## 4. 把东西交出去

把 `share.json` 发给他，配这段话：

> 这是那份报告。你打开 `verify.html`（或者把 share.json 拖进去），
> 它会**在你自己的浏览器里**重算每个文件的哈希——不需要装东西，不需要注册。
>
> 重点是：**你不需要相信我这个工具**。报告从生成到现在有没有被改过，
> 是你自己算出来的。
>
> 你拿去给客户看也行。如果客户问"我怎么知道这不是你改过的"，这个页面就是答案。

**该看什么**：他有没有真的打开。

如果他不打开 → 说明"可验证"不是他买的原因。这是一个非常重要的负信号：
那就改卖"帮你把权限收紧"，别卖证据。

## 5. 一周后跟进（这句话决定你拿到什么）

> 那份报告你后来用上了吗？客户那边有没有问起过？

然后，**无论他答什么，问这一句**：

> 如果下次再要做一次，你会自己跑这个流程，还是想让我来做？愿意为它付多少钱？

这是整个流程唯一一次问钱。问在**他已经用过之后**，而不是之前——
之前问，你得到的是想象；之后问，你得到的是参考点。

---

## 6. 每次都要记（否则三次做完什么也没学到）

记到 [delivery-log.md](delivery-log.md)。**必须记的是负信号**：
哪个环节对方不感兴趣、哪句话让他尴尬、哪一步他想跳过。

## 7. 三次之后怎么判断

| 结果 | 含义 | 下一步 |
|---|---|---|
| ≥1 人主动问"多少钱"或"下次还能不能做" | 有需求 | 把它产品化：定价、把流程再缩短 |
| 3 人都收下了、都没打开验证链接 | **"可验证"不是买点** | 改卖权限收敛，别卖证据 |
| 3 人都说"挺好"但没有任何后续动作 | 这是礼貌，不是需求 | 换人群（从乙方换成自己要过合规的团队） |
| 有人明确说"我的场景用不上" | 画像错了 | 让他描述他真正的痛点，比你自己猜有用 |

**60 天 0 付费 = 停下来。** 不是继续改产品，而是承认这个买家不存在。

## 8. 会被问到的问题（提前想好答案）

| 他问 | 你答（照着说，别加戏） |
|---|---|
| 这跟 Snyk 的扫描有什么区别？ | 扫描告诉你暴露面；这个告诉你**该允许什么**——它从你的实际调用里编译策略。 |
| 数据会不会传出去？ | 不会。报告在你机器上生成，验证也在你浏览器里算。 |
| 准吗？ | 策略是启发式编译的，所以每条判定都写了依据，依据不足的会被单列出来让你确认。**它不替你做决定。** |
| 我用了会打断我的 agent 吗？ | 采集 hook 出错也静默退出，不影响你的工作流。 |
| 能管住 agent 吗？ | **不能。** 它不是沙箱、不拦调用。它管的是"权限该开多大"和"留下可验证的记录"。 |

最后一条很重要：**主动说清做不到什么**。这是唯一能让对方相信你其他话的方式。
