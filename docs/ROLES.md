# 三个角色，一套台账（先把词定死）

> 这份文件存在的唯一理由：**同一个东西被叫过好几个名字**，讨论就会崩。
> 下面每行都写清"它是什么、跑在哪、现在能做什么、不能做什么"。
> 术语以本文件为准；代码、帮助文本、页面、文档一律照这里改。

## 一句话

```
  被管的机器                          集群里                     收货方那边
┌──────────────────────┐        ┌──────────────────┐      ┌────────────────┐
│  Agent 侧            │ 元数据 │  控制面（server）│ 凭据 │  收货方         │
│  · ratchet CLI       │ ─────▶ │  · asas-api      │ ───▶ │  · 验证页       │
│  · 传感器（无人值守） │  证据  │  · 控制台页面     │      │  · 离线验证器   │
│  **只读观测**        │  事件  │  **汇总 + 复算**  │      │  **不信任签发方**│
└──────────────────────┘        └──────────────────┘      └────────────────┘
```

## 1. Agent 侧（你说"client"时指的应该是这个）

**跑在被管机器上**：开发者的笔记本、CI runner、或者"节点就是宿主机"的服务器。

| 组件 | 是什么 | 现在能做什么 |
|---|---|---|
| `ratchet` CLI | 一个 Go 单二进制 | 盘点 agent 与 MCP server；把真实行为编译成最小权限策略；产出凭据；把调用记录变成带哈希链的事件流 |
| 传感器 | 同一套动作的无人值守形态（脚本 / 容器镜像 / 集群 CronJob） | 定时采集 → 出证 → 上报控制面 → 传证据与事件 → 复验 |

**它现在做的**：观测 + 出证 + 上报 + **拦截**。

**执行点（`ratchet guard`）**：挂在 agent 的 PreToolUse 上，在工具**执行之前**
给出 `allow` / `ask` / `deny`。判定顺序、目标分类、失败模式、覆盖边界见
[GUARD.md](GUARD.md)——那份文件是这块的单一事实来源。

* **能拦住的**：命中不可恢复目标（备份、转储、数据目录、生产目录、`.git`）或
  凭据类目标（`.env`、私钥、云凭证）的调用；破坏性动作且目标不在安全清单内时，
  至少停下来等人确认。
* **它的边界**：只覆盖走 agent 钩子的调用。人自己敲的命令、cron、别的 agent 不在范围内；
  命令分析是启发式的，精心构造的规避绕得过去；**它不是沙箱**。

**观测侧仍然是只读的**：`ingest` 挂在 PostToolUse 上，纪律是"绝不阻塞 agent"，
写盘失败也只是往 stderr 说一句。执行点是**另一个命令、另一条纪律**——
它在判定为拒绝时必须真的拒绝。两者共用同一份策略，所以不会出现
"策略说拒、执行点不认"这种静默失效。

**凭据里仍然写着 `boundaries.mode = "readonly"`**：那是**观测侧**的自述，如实反映了
"这一侧不碰调用链"。执行点的能力写在策略文件的 `guard` 段里，两者不混为一谈。

## 2. 控制面（server）

**跑在集群里**，一个进程：`asas-api`（Python 标准库，台账落 PVC）。

| 它是什么 | 说明 |
|---|---|
| `/attestations` `/verify` | 收凭据、用**同一份规则实现**复算（与 CLI 逐字一致） |
| `/evidence` `/events` | 收证据文件与事件流，让 `hashMatch`、`silenceIsAuditable` 可被评估 |
| `/silence` | 每条事件链的摘要 + **跨次比对**发现的改写/截断 |
| `/contain` `/reach` | 遏制编排（级联）与"谁曾能触达 X" |
| **控制台页面（`/`）** | **它就是控制面的一部分**，同一个进程提供；不是第四个东西 |

**它现在做的**：汇总、复算、跨次比对、遏制**记录**、查询。

**它现在不做的**：真正把某个 agent 踢下线——那要落在客户的身份系统里。
控制面记下"已吊销"这个事实（并级联到下级），执行在客户那边。

## 3. 收货方

客户的安全负责人、审计员、甲方。

| 形态 | 地址 / 方式 |
|---|---|
| 验证页（零安装，拖文件进去） | https://podcloud.dlszjr.com/verify |
| 离线验证器 | `python3 verify.py <交付目录>`（随交付物一起给） |

**不需要**控制面，也不需要装任何东西——这正是整套东西的卖点。

## 4. CLI 的两个面（混乱的最大来源）

同一个二进制里，命令其实分两类。**用的时候要清楚自己在哪一面**：

| 面 | 命令 | 在哪跑 | 要不要连控制面 |
|---|---|---|---|
| **采集面** | `scan` · `deliver` · `chain` · `ingest` · `observe` · `policy` · `mcp` | 被管机器 | 不用（可以完全离线） |
| **台账面** | `reach` · `contain` | 任意有网络的机器 | 要（`--api` 或 `ASAS_API`） |

采集面**绝不**因为控制面连不上而失败——采集是本地事实，先出凭据，再谈上报。

## 5. 命名对照表（旧名字一律作废）

| 旧叫法（造成混乱） | 现在叫什么 |
|---|---|
| client、客户端、agent 端 | **Agent 侧** |
| sensor、传感器、采集器 | **传感器**（是 Agent 侧的一种形态） |
| server、服务端、asas-api、控制面 | **控制面**（进程名 `asas-api`） |
| UI、控制台、页面 | **控制台**（控制面的一个页面） |
| 验证方、收货方、审计员 | **收货方** |
