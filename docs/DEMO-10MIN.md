# 十分钟演示脚本（给客户 / 投资人）

> 目标：**十分钟内让人明白这是什么、并且亲眼看到它成立。**
> 每一段都写清「说什么 / 做什么 / 预期看到什么」。不要把命令念出来，让它跑就行。
> 全程只用两个东西：控制台页面，和一个终端。

## 0. 先给一句话（30 秒，不要展开）

> "企业把 agent 接进业务系统以后，被客户或审计问同一句话：**这些 agent 到底被允许碰什么，
> 你凭什么这么说？** 今天我们卖的是这个问题的**可交付答案**——
> 一份**别人不用信我们、自己就能验**的凭据。"

如果对方问"那你们拦不拦？"——直说（这一条不能说反，说了后面全崩）：

> "**现在不拦。** 第一步是让'能碰什么'变成可证明的事实。拦要有执行点，
> 那是下一级的工程，也是我们路线图上明确写着的。"

## 1. 打开控制台（1 分钟）

**做**：浏览器打开 `http://127.0.0.1:30090`（客户环境里是你部署的地址）。

**预期看到**：页头是**控制面（server）**；一行读数（凭据 / 事件链 / 断流 / 遏制）；
一条"这不是防火墙"的定位；下面两步接入指引；再下面是查询条与台账。

**说**："左边这些问题（谁碰过什么）我们等下再看。先看**买方视角**——"

## 2. 打开验证页：让收货方自己验（2 分钟）

**做**：新开一个标签页，打开 https://podcloud.dlszjr.com/verify ，
把一份交付目录里的 `attestation.json` 拖进去（或用 `python3 verify.py <交付目录>`）。

**预期看到**：九条规则逐条给出通过 / 不通过 / **未评估**，并且**不需要登录、不需要装东西、
不需要我们在线**。

**说**："注意第三条状态：**未评估**。我们没有证据文件时它不写'通过'——
这正是这套东西和一份漂亮 PPT 的区别。"

## 3. 在被管的机器上跑一条命令（2 分钟）

**做**：

```bash
ratchet deliver --out /tmp/v --home "$HOME" --client 客户名 \
  --report-cmd "python3 -m ratchet_service.cli"
```

**预期看到**：`scan → observe → chain → policy → report → attest`，最后给出交付目录与分享包。
如果本机有未定版组件，`attest` 会**如实报不通过**并点名是哪个组件。

**说**："这一步就是客户要做的全部动作——一条命令。它读的是**这台机器真实的配置**，
不是问卷。"

（想让它变成"通过"：加 `--exempt "名字=到期日"`，书面豁免——**豁免是写进凭据的**，
收货方看得见，到期即失效。）

## 4. 交给控制面：同一份规则复算（1.5 分钟）

**做**：按控制台"两步接入"里那条 `curl` 把它交上去；回到控制台，点台账里那一行。

**预期看到**：右边出现这份凭据的**九条规则与依据**。点"重新验证这份凭据"→
提示"与上面这份完全一致——同一份规则、同一份输入"。

**说**："控制面**没有第二套规则**。它做的是把输入凑齐：
证据、事件流、父凭据、遏制记录。证据一上传，`hashMatch` 就从'未评估'变成'通过'。"

## 5. 谁碰过 X（1 分钟）

**做**：在查询条里输入一个真实资产名（比如某个 MCP server），回车。

**预期看到**：**能（授权面）** / **确实用过（观测面）** 分列，每条带"依据：哪份凭据"。
如果台账没覆盖这个资产，会明确写"**这不等于没人能碰它**"。

**说**："事故里第一句话是'谁碰过这个'。我们把'被授权'和'真的用过'分开列——
两者不一致本身就是结论：能碰但从没用过（可以收回的权限），或者用过却不在授权里（有人绕过了配置）。"

## 6. 篡改演示：沉默可被审计（1.5 分钟，最能打的一段）

**做**：改一条本地调用记录（把一条 `deny` 改成 `allow`），再跑一次采集。

**预期看到**：`❌ 检出断流：本地日志被改写：N 条与上次不一致（seq …）`，
控制台顶部"断流"计数加一，断流区出现"上次的摘要 → 这次的摘要"。

**同时要说**：**这一趟的凭据自己仍然是"通过"**——链是自洽的。
改写是靠**跨次比对**发现的，这就是为什么需要一个持续存在的台账。

## 7. 遏制：先看会连累谁（1 分钟）

**做**：在凭据面板点"遏制预演（只看会连累谁）"。

**预期看到**：连带名单（本人 + 下级，标注来自哪条委派边）+ 真的动手要敲的命令。

**说**："预演**不写库**——高危动作先看再执行。真吊销会级联到下级：
只拿下被点名的那一个，等于把最容易漏掉的部分留着。"

## 8. 收尾：三级路线图（30 秒）

> "**第 1 级（今天就能交付）**：一台机器一条命令出一份可被第三者独立验证的凭据。
> **第 2 级（今天也在跑）**：控制面把多台机器、多天的凭据汇成台账，
> 做跨次比对、触达查询、遏制记录。
> **第 3 级（还没有）**：执行点——代理/网关/SDK 拦截，把'能碰'变成'只能碰'。
> 我们故意把它放在后面：**说不清能碰什么，就别谈拦住它。**"

## 演示前检查（1 分钟，别现场翻车）

```bash
curl -sS http://127.0.0.1:30090/healthz         # {"status":"ok"}
kubectl -n asas get deploy asas-api             # 1/1 Running
ratchet version                                 # 与页面上的版本号一致
```

* 控制台与验证页**都提前打开好**，别在投屏时输地址。
* 演示用的交付目录提前生成一份（`/tmp/v`），第 2 步直接拖。
* 第 6 步改日志之前，**先把当前摘要念出来**——不然后面"变了"没有对照。

## 不要说的话（说了就自相矛盾）

* "我们帮你拦住 agent"——现在没有执行点。
* "装了我们就有合规"——标准只声明**可支撑**哪条要求，从不声称合规。
* "我们的平台越大越准"——控制面是单租户台账，不做跨客户情报（明确排除）。
