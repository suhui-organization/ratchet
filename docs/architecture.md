# 系统设计：Agent Security Control Plane

> 这份设计对应 [ASAS v0.1](../spec/ASAS-v0.1.md)。标准是"要求"，本文是"怎么实现这些要求"。
> 五项已定决策见文末 §7。

## 1. 五条设计原则

1. **只有可验证的东西才有价值**——凭据必须能被第三方离线验证，不依赖信任我们。
2. **未知必须显式**——隐藏未知等于审计欺诈；`unknown` 是一等状态。
3. **只采元数据**——结构体里根本不存在参数值与内容字段（由 schema 强制）。
4. **旁观者必须独立**——传感器不受被监控的 agent 控制。
5. **先单租户价值，后网络红利**——跨客户情报是复利，不是第一天能卖的东西。

## 2. 组件与数据流

```
[客户环境]
  Agent（现成产品 / 自研） · MCP servers · skills · 凭据
        │ ①只读观察（v1 不拦截）
        ▼
  Sensor = 容器 sidecar（首选）/ daemon / CLI 按需
        │ 事件哈希链 + 本地只增摘要（客户自己留存）
        │ ②HTTPS 上报：仅元数据，字段可逐项关闭
        ▼
[控制面 SaaS]
  Ingest → Normalize → 租户隔离存储
     ├─ Inventory / Identity 台账            ASAS-1
     ├─ Policy Center（编译·版本·下发）        ASAS-2
     ├─ Drift & Re-attest 触发器              ASAS-3 / 6.5
     ├─ Attestation Service（生成·签名·发布）   ASAS-6
     ├─ Verification Endpoint（离线可验，服务只为方便）
     └─ Correlation（跨租户，仅共享"模式"）     红利层
        │ ③规则 / 策略回灌
        ▼
  Sensor · CI Gate · Gateway        ← v1 的拦截点只有 CI 门禁
```

## 3. 数据模型

| 实体 | 关键字段 | 对应控制项 |
|---|---|---|
| Org / Tenant | 组织、环境、保留策略 | 隔离与合规 |
| Agent | id、责任人、运行时、身份引用、`registered` | ASAS-1.1–1.3 |
| Identity (NHI) | 类型、`shared`、轮换时间 | ASAS-1.4 |
| Asset | kind、name、version、`pinned`/`exemptUntil`、`contentHash`、**`descHash`** | ASAS-3.1–3.3 |
| Delegation | from、scope、expires | ASAS-2.4 / 2.5 |
| Policy / Verdict | 默认决策、规则、**basis** | ASAS-2.1 / 2.2 |
| Observation | tool、count、首末次、**argKeys（无值）** | ASAS-5.1 / 5.2 |
| Signal | s1–s6、count、severity | 中心分析 |
| Attestation | ASAS-A 文档 + manifest | ASAS-6 |

## 4. 客户端形态（按企业可批准性排序）

| 形态 | 定位 | 结论 |
|---|---|---|
| **容器 sidecar** | 主传感器（v1 首发） | **首选**——进 CI/K8s，不碰开发者笔记本 |
| 常驻 daemon | 更广的覆盖 | 次选，需要 MDM 与安全评审 |
| CLI 按需 | 取证、一次性审计 | 保留，**不做持续监控** |
| MCP server | **只读查询接口** | **绝不做传感器**——被监控者不该掌握监控开关 |

## 5. 数据边界（写进产品与合同）

- **采**：工具名 / 版本 / 哈希、判定与依据、委派、计数、时间、环境。
- **不采**：参数值、返回值、提示词、模型输出、文件内容、任何业务数据。
- **可验证的沉默**（ASAS-6.6）：事件带单调序号 + 前序哈希；客户本地留存只增摘要；中心可发现断裂；审计员可导出比对——**能证明没被删改，也能证明没有断流**。

## 6. 分阶段：每阶段必须能单独卖

| 阶段 | 内容 | 卖点 |
|---|---|---|
| **P0** | 传感器 v0（只读、容器优先、`--introspect` 默认不执行）+ 凭据生成 + 离线验证器 | 一次性审计 / OPC 交付证据 |
| **P1** | 单租户控制面 + **CI 门禁**（拦截未定版供应链变更） | 团队版订阅——**第一个有拦截的服务** |
| **P2** | 委派边界 + 遏制编排（回答 95% 那个"关不住"） | 企业版 |
| **P3** | 跨租户模式关联 + 规则回灌 | 红利层，网络效应 |

## 7. 已定的五项决策（2026-09-20）

1. **命名**：标准叫 **ASAS**，附件 `ASAS-A`（凭据格式）/ `ASAS-V`（验证程序）。
2. **中立化时点**：出现 **1 个外部实现 + 1 个审计方引用**后，立即移交 OWASP / CSA。
3. **认证业务**：**愿意为竞争对手的实现盖章**（否则它不是标准）。
4. **v1 包含 CI 门禁**：必须有拦截点，否则永远停在"仪表盘预算"。
5. **传感器首发形态**：**容器 sidecar**（企业易批），CLI 保留做取证的按需工具。

## 8. 与既有实现的关系

现有 `ratchet` 已经完成 P0 的约 80%：`scan` / `observe` / `policy draft`（三态 + 依据）/ `deliver`（哈希清单 + 零安装浏览器验证）。

**缺口清单**（也是下一轮的开发对象）：
1. 产物外壳对齐 `ASAS-A-v0.1`（含 `unknown[]`、`descHash`、`delegations`）；
2. ASAS-V 离线验证器（6 条规则）+ 20 条测试向量；
3. 传感器容器化（`--introspect` 默认不执行，改显式 `--allow-exec`）；
4. CI 门禁（未定版新增 → 退出码非 0 + SARIF 输出）。
